# Sprint 2 integration checkpoint ([QA 2.1], #109)

Results from two real-Hub runs on November 16, 2026. The [Desktop run](https://github.com/BootlegYouki/L.A.R.A/issues/109#issuecomment-6921608638) used separate Windows PCs on a classroom router with the WAN cable unplugged. The [cross-platform run](https://github.com/BootlegYouki/L.A.R.A/discussions/312) used the native Windows app and a physical Android phone on classroom Wi-Fi. The WAN cable was not confirmed unplugged for that run.

| Check | Result | Evidence |
|---|---|---|
| Hub connectivity | PASS | Desktop found the real Hub automatically and connected by manual address on the isolated LAN. Both native clients discovered the Hub in the cross-platform run. |
| Create a teacher in the Hub window and sign in on both clients | PASS | On November 17, the native Windows Hub window set up the admin and created a synthetic teacher in a fresh database. Both the Android x86-64 debug APK and the standalone Windows Desktop release build from `a35b450` signed in as that teacher and displayed the synthetic class. The emulator's `10.0.2.2:8080` route returned Hub unavailable on this host. Manually entering `127.0.0.1:8080` with ADB reverse forwarding to the real Hub worked. |
| Create class, request to join, approve and open the class | PASS across the two runs | Desktop created a class and completed the join and approval flow with two Desktop clients. In the cross-platform run the class was created through the Hub API, the Android learner requested access, Desktop approved it, and Android opened the class without a restart. |
| WebSocket and delta pull | PASS | The cross-platform protocol check observed `EVENT_JOIN_REQUEST`, `EVENT_JOIN_APPROVAL` and the active enrollment in the learner's delta pull. A November 17 follow-up started the real Rust Hub with a fresh synthetic database, approved a learner, then connected and disconnected the learner's WebSocket. The teacher's authenticated socket received `EVENT_PRESENCE` with `ONLINE` and `OFFLINE`, the expected class and learner IDs, and integer timestamps. |
| Interrupt pull and push mid-sync and verify database integrity | NOT VERIFIED | Desktop retained its saved data and reconnected after the Hub stopped. The [maintainer deferred the mid-sync Wi-Fi test](https://github.com/BootlegYouki/L.A.R.A/issues/109#issuecomment-6935618456). |
| Upgrade desktop with existing data | SQLITE AND BUILDS PASS, LIVE MSI NOT VERIFIED | On November 17, migration 004 from staging merge `a35b450` ran against a populated SQLite database created with migrations 001–003 from `6f0c2cb`. Saved classes, enrollment, queued quiz answers and private comments survived, the tested timestamps were backfilled, and SQLite reported no foreign-key violations. Both x64 MSI packages built. Windows Installer rejected the first attempt with error 1324 for the destination path. Automatic approval review blocked the corrected per-machine installation retry because the current session lacked administrator elevation. The maintainer requested a live MSI upgrade for [PR #313](https://github.com/BootlegYouki/L.A.R.A/pull/313) by November 19. |

The cross-platform run recorded a Desktop schema test failure addressed by PR #313. The [maintainer's follow-up](https://github.com/BootlegYouki/L.A.R.A/issues/109#issuecomment-6935618456) accepted the same-PC multi-instance limitation, requested a reproduction for the Archived Classes sidebar finding, and confirmed the garbled sign-in loading text for a bug report.

## How to repeat the remaining checks

1. Start the Hub window with a fresh test database and complete admin setup. Create a teacher from the Hub window. On Desktop and an Android emulator, enter the Hub address manually and sign in as that teacher.
2. Create a class in the teacher app. On the Android client, use a synthetic learner to request access. Approve from Desktop, then open the class on Android. Capture the join request, approval and presence events in the Hub or client test logs.
3. With test data, interrupt the connection during a pull and again during a push. Check the saved rows and sync cursor immediately after each interruption, then reconnect and confirm retries apply the intended changes once.
4. On a test PC or VM, install the MSI built from `6f0c2cb`. Sign in and join or create a class. Install the MSI containing PR #313 over it using the same Windows account. Open the app and confirm the saved classes are still available.
