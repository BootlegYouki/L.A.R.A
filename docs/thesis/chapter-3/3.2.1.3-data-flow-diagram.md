# 3.2.1.3 Data Flow Diagram

The data flow diagrams describe how the proposed Hub receives, processes, and stores classroom information. The level 0 diagram divides the Hub into seven processes. Gane-Sarson notation distinguishes processes, external entities, and data stores. A combined arrow represents the related input and output exchanged by one pair of elements. Repeated entity and store symbols are marked with an asterisk and refer to the same actor or logical store.

![Figure 3.x: Level 0 data flow diagram of the proposed Hub.](diagrams/dfd-level-0.png)

*Figure 3.x. Level 0 data flow diagram of the proposed Hub.*

**1.0 Manage Accounts & Enrollment.** This process manages learner registration, authentication, teacher accounts, classroom membership, and enrollment decisions. Account and session information is maintained in D1, while classroom ownership, co-teacher membership, and enrollment status are maintained in D2. Class access follows the Teacher's approval of the Learner's join request.

**2.0 Manage Stream.** This process distributes Teacher announcements and manages permitted Learner and Teacher comments. D3 stores the announcements and their comments. The Teacher controls whether commenting is allowed on an announcement.

**3.0 Manage Classwork.** This process organizes topics, lesson materials, assignments, homework submissions, private comments, grades, and feedback in D5. Lesson files are retained in Hub-managed storage, while their descriptive records identify the associated classwork. The Hub extracts lesson text for tutoring, supports video seeking and download, and receives homework completed while a device is disconnected. Private comments are limited to the relevant Learner and the class Teachers.

**4.0 Run Quizzes.** This process supports quiz authoring, activation, attempt creation, answer submission, objective grading, closing, and score release. D4 holds quiz settings, questions, and attempts. Answer keys are available only to the owning Teacher and remain excluded from Learner-facing quiz information. An active attempt also provides the state used to block the Socratic tutor during a quiz.

**5.0 Gradebook, Export & Backup.** This process assembles quiz and homework points into a gradebook file in spreadsheet or comma-separated format. The file is either downloaded to the Teacher's device or saved to the USB Drive. Backup reads all Hub data stores and the associated files to produce a restorable archive. Restoration verifies the archive, restores the saved information, and updates the synchronization epoch.

**6.0 Socratic AI Tutor.** This process checks classroom access and quiz lockout before answering a Learner's question. It uses the Teacher's lesson text in D5 and retains Hub-assisted conversation records in D6. Requests enter a bounded first-in, first-out queue. Each response provides one small clue followed by a guiding question in the selected language. Questions outside the lesson's coverage are redirected to the lesson. Model unavailability does not prevent other classroom activities.

**7.0 Synchronize Devices.** This process receives queued work, returns acknowledgements, and distributes authorized classroom updates. D7 supplies the ordered change revisions, and D8 supplies the Hub identity and synchronization epoch. The cursor is a sequence position rather than a timestamp. Each device applies an update page and its next cursor in one local transaction, preserving queued work until it is acknowledged.

| Logical store | Contents |
|---|---|
| D1 Accounts & Sessions | Account identities and authentication sessions. |
| D2 Classes & Enrollment | Classrooms, co-teachers, and enrollment decisions. |
| D3 Stream | Announcements and announcement comments. |
| D4 Quizzes | Quiz settings, questions, attempts, and scores. |
| D5 Classwork | Topics, materials, lesson chunks, assignments, submissions, and private comments. |
| D6 Tutor History | Hub-assisted questions and tutor responses. |
| D7 Sync Ledger | Ordered classroom changes and removal notices. |
| D8 Hub Identity | Hub identity and synchronization epoch. |

![Figure 3.x: Level 1 decomposition of Run Quizzes.](diagrams/dfd-level-1-run-quizzes.png)

*Figure 3.x. Level 1 decomposition of 4.0 Run Quizzes.*

The quiz process begins when the Teacher authors and activates a quiz. The Hub sets **quizzes.started_at** from its own clock at activation. Beginning an attempt creates the **IN_PROGRESS** state, which prevents access to the AI tutor. The Learner's completed answers enter the same validation and grading path whether submitted immediately or delivered from an offline queue. The timing check is **submitted_at − quizzes.started_at ≤ duration + 60 seconds**. Accepted answers are compared with the Teacher's keys, and the resulting attempt, score, and change revision are committed together. Closing a quiz submits the remaining attempts and releases scores that the Teacher has held. A remote device uses the Hub-provided start time for its local countdown.

![Figure 3.x: Level 1 decomposition of Synchronize Devices.](diagrams/dfd-level-1-synchronize-devices.png)

*Figure 3.x. Level 1 decomposition of 7.0 Synchronize Devices.*

Synchronization first resolves the account and classroom access of the requesting device. Queued quiz attempts, comments, and private comments are validated through their corresponding classroom processes, while homework files follow the submission transfer. The Hub returns an acknowledgement or a rejection reason for each queued item. For an update request, the Hub checks its identity and epoch, retrieves permitted changes after the sequence cursor, and returns the update page and next cursor. The device applies both in one transaction. A reset rebuilds the local mirror while retaining work marked **QUEUED_FOR_SYNC**. Interrupted transfers or connections therefore preserve local work for a later exchange with the Hub.
