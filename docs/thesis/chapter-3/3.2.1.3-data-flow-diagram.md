# 3.2.1.3 Data-Flow Diagrams

The context diagram in Section 3.2.1.2 is the Level 0 view: it treats the L.A.R.A. Hub as one process and shows exchanges across the system boundary. The Level 1 diagram decomposes that process into eight major workflows and names the data stores using the actual tables in `contracts/schema/server_master.sql`. Repeated actor references marked with an asterisk represent the same external entity in separate process rows. Each Level 2 diagram expands one Level 1 process. Arrow labels identify the data exchanged; a two-way exchange is represented by separate arrows where direction differs.

![Figure 3.x: Level 1 data-flow diagram of L.A.R.A.](diagrams/dfd-level-1-overview.png)

*Figure 3.x. Level 1 data-flow diagram showing the Hub processes, external entities and contract data stores.*

| Process | Main input and output at the system boundary | Contract tables and files |
|---|---|---|
| 1.0 Accounts and authentication | Learner, Teacher or Admin credentials and setup details; returns session or operation result | `users`, `sessions` |
| 2.0 Class and enrollment | Learner class-code request and Teacher class or decision; returns enrollment state, class access and roster | `classrooms`, `classroom_teachers`, `enrollments` |
| 3.0 Stream, materials and video | Teacher content changes and Learner/Teacher reads; returns announcements, comments, material metadata, downloads and video ranges | `announcements`, `announcement_comments`, `topics`, `materials`, `material_chunks`, Hub-managed files |
| 4.0 Assignments and homework | Teacher assignment and grading changes; Learner file submissions and private comments; returns assignment data, own thread and feedback | `assignments`, `assignment_submissions`, `private_comments`, Hub-managed files |
| 5.0 Quizzes and grading | Teacher quiz authoring and control; Learner attempts and answers; returns quiz state, progress and permitted score | `quizzes`, `quiz_questions`, `quiz_attempts`, `sync_revisions` |
| 6.0 Lesson tutor | Learner lesson question; returns a streamed guided response or a refusal/lockout result | `material_chunks`, `quiz_attempts`, `ai_chat_messages`, Hub model process and queue |
| 7.0 Synchronization | Mobile/Desktop queued writes and cursor; returns receipts, authorized updates and next sequence cursor | `sync_revisions`, `hub_meta`, and the affected classroom tables |
| 8.0 Export and backup | Teacher export request, Admin backup/restore request, or USB archive; returns a download, file or operation result | Classroom tables, `hub_meta`, Hub-managed files and USB target path |

*Table 3.x. Level 1 processes, boundary flows and contract-backed data stores.*

## Level 2 decompositions

### 1.0 Accounts and authentication

![Figure 3.x: Level 2 data-flow diagram for accounts and authentication](diagrams/dfd-level-2-accounts.png)

*Figure 3.x. Level 2 decomposition of account creation, session validation and authorization.*

The Hub validates registration or sign-in details, creates or verifies a session, and applies role and class-scope authorization before protected operations. User identities and hashed bearer sessions are stored in `users` and `sessions`; PIN hashes remain Hub-side.

### 2.0 Class and enrollment

![Figure 3.x: Level 2 data-flow diagram for class and enrollment](diagrams/dfd-level-2-class-enrollment.png)

*Figure 3.x. Level 2 decomposition of classroom and enrollment operations.*

The Hub creates or retrieves a classroom, records a Learner's join request, and records the Teacher's approval, rejection or removal decision. It then returns the permitted roster and class access state. The corresponding records are `classrooms`, `classroom_teachers` and `enrollments`.

### 3.0 Stream, materials and video

![Figure 3.x: Level 2 data-flow diagram for stream, materials and video](diagrams/dfd-level-2-stream-materials.png)

*Figure 3.x. Level 2 decomposition of stream, material and video delivery.*

Teacher content is stored in announcement, topic and material records. The Hub extracts available text from uploaded documents into ordered `material_chunks`. It authorizes material download and video byte-range requests before sending file data. It does not assume extractable text for every file.

### 4.0 Assignments and homework

![Figure 3.x: Level 2 data-flow diagram for assignments and homework](diagrams/dfd-level-2-assignments.png)

*Figure 3.x. Level 2 decomposition of assignments, submissions, private comments and grading.*

The Hub stores assignment settings, accepts a submission with its client-generated identifier, and validates access to the assignment's private thread. A class Teacher reviews and grades the submitted file. Learners receive only their own score and feedback. Offline writes are retried through synchronization and their result is acknowledged or rejected by the Hub.

### 5.0 Quizzes and grading

![Figure 3.x: Level 2 data-flow diagram for quizzes and grading](diagrams/dfd-level-2-quizzes.png)

*Figure 3.x. Level 2 decomposition of quiz authoring, attempts, validation and score release.*

The Teacher creates a draft and its questions, then starts or closes the quiz. A Learner begins one attempt and submits answers. The Hub validates the attempt against the server-recorded start time and duration, grades objective answers, and stores the attempt. Scores are returned immediately only when the release setting allows; otherwise they remain held until release. A successful change is recorded in `sync_revisions` within the same database transaction.

### 6.0 Lesson tutor

![Figure 3.x: Level 2 data-flow diagram for lesson tutoring](diagrams/dfd-level-2-tutor.png)

*Figure 3.x. Level 2 decomposition of lesson-grounded tutoring and quiz lockout.*

The Hub authorizes the Learner and classroom, checks for an in-progress quiz attempt, selects relevant lesson chunks, and submits the request to its bounded inference queue. The Hub streams the response and stores the conversation record. If a quiz attempt is in progress, it refuses the request; if lesson text does not support a response, the tutor directs the Learner back to the lesson.

### 7.0 Synchronization

![Figure 3.x: Level 2 data-flow diagram for synchronization](diagrams/dfd-level-2-sync.png)

*Figure 3.x. Level 2 decomposition of queued writes and ordered change delivery.*

After authentication, the Hub applies each queued write through the process that owns that record and returns an item receipt. For a pull, it checks the Hub identity and epoch, selects authorized changes after the integer sequence cursor, and returns the update page with `next_cursor`. Clients apply the page and cursor in one local transaction. A reset preserves queued and rejected work while rebuilding the mirrored data.

### 8.0 Export and backup

![Figure 3.x: Level 2 data-flow diagram for export and backup](diagrams/dfd-level-2-export-backup.png)

*Figure 3.x. Level 2 decomposition of class-record export and Hub backup or restoration.*

The Hub assembles a Teacher's class record as XLSX or CSV and either returns it for download or writes it to the requested mounted path. Separately, the Admin can create a backup archive or request restoration from an archive. Restoration verifies the checksum and advances `hub_meta.sync_epoch` so clients perform a full synchronization.

The Level 2 diagrams preserve each parent process's external exchange: actors and USB storage remain outside the Hub boundary, while the process reads or writes only the named contract tables and Hub-managed files. Tables are shown as stores, not as external services. The client-only cache tables are not Hub stores and therefore do not appear in this Hub DFD.
