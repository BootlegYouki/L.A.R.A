# 3.2.1.8 Requirements Mapping to Resources

This table connects the product requirements to the hardware, software and classroom facilities needed to operate the system. Values explicitly specified by the project are separated from deployment assumptions. A 16 GB Hub PC is the evaluation target for the current model candidate; the final model and its performance remain subject to the required Hub evaluation.

| Requirement | Hardware and device specification | Software specification | Facility and network specification |
|---|---|---|---|
| Account access, class creation and enrollment | One dedicated, always-on Hub PC; Android phones and school or personal laptops for Learners and Teachers | Hub authentication and classroom REST routes; Android Mobile and Tauri Desktop clients; local SQLite mirrors | Classroom LAN; Hub reachable on TCP 8080 and WebSocket TCP 8081; mDNS and UDP discovery on port 8888; manual Hub address available |
| Stream, modules and video | Hub disk sized for uploaded materials; client local storage for saved resources; phones and laptops with Wi-Fi | Hub-managed files, HTTP Range video service, Android Media3 and Desktop webview video playback | Wi-Fi coverage for the classroom; WAN connection is not required for LAN use |
| Assignments and homework | Android phone camera or supported image/document file; Hub storage for submitted work | Android CameraX capture; local queue and Hub submission routes; manual grading and feedback | Hub connection for transfer and grading; queued work is delivered after reconnection |
| Quizzes and grade monitoring | Hub PC and classroom phones/laptops; load evaluation uses up to 40 simulated clients | Hub quiz and grading routes; client local attempt storage; teacher result monitoring and learner own-score views | Stable classroom Wi-Fi; REST/WebSocket access to the Hub; local countdown can continue through disconnection |
| Lesson tutoring | Dedicated Hub PC with 16 GB RAM for the current evaluation candidate; no model inference requirement on client devices | Hub-managed `llama-server` queue and WebSocket stream; local model choice remains subject to evaluation | Local Hub access; tutor unavailable when the Hub cannot be reached and locked during a Learner's active quiz attempt |
| Offline study and synchronization | Phone or laptop local storage for the account-scoped database and downloaded resources | Android Room; Desktop `@tauri-apps/plugin-sql`; integer sync cursor; queued writes use `QUEUED_FOR_SYNC` | Classroom LAN for discovery and later synchronization; cached reading remains available when disconnected |
| Class-record export and Hub backup | Hub PC storage and one USB flash drive; the planning budget estimates a 32 GB drive | XLSX/CSV class-record export, `.lara-backup` archive and checksum-verified restoration | USB mount/path accessible to the Hub; stable AC power for the always-on Hub and router |
| Zero-internet classroom operation | Hub PC, client devices and Wi-Fi router | Bundled application assets and local Hub services; no external classroom service is required | Isolated Wi-Fi LAN or peer hotspot; external WAN connection may remain unplugged |
| Remote/Suspension Mode | Same Hub and client hardware | Optional Hub-managed `cloudflared` tunnel | Admin opt-in; remote URL is a fallback after local discovery fails; tunnel is the only approved external path |
| Mobile resource limits and accessibility | Representative Android phone with 3 to 4 GB RAM; measured heap below 250 MB | Android 8.0/API 26 minimum, API 35 target; bundled interface assets and English strings | Classroom network is not required for opening previously saved work |
| Hub reliability and recovery | Dedicated Hub PC, SSD and classroom router; the project cost plan includes a 650 VA UPS as an estimate | SQLite-backed Hub, automated backup and restore operations | Mains power and a suitable outlet for Hub/router; UPS is a planning item rather than a contracted runtime prerequisite |

*Table 3.x. Functional and non-functional requirements mapped to hardware, software and facility resources.*

| Media3 ExoPlayer | 1.5.1 | Android video playback |
| Android SDK | minimum API 26; target API 35 | Supported Android platform range |

*Table 3.x. Software baseline recorded in the project manifests and build configuration.*

The repository does not specify minimum CPU, RAM or operating-system versions for Learner and Teacher laptops. Those values must be established through representative-device evaluation rather than inferred from the use of Tauri. The model-selection evaluation also determines whether the stated Hub memory target is sufficient for the final tutor model.
