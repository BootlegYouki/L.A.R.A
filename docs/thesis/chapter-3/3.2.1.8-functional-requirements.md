### Technology Requirements Specification

| Other Technology Used | Specification | Descriptions |
|---|---|---|
| HTTP/1.1 REST API | Hub service on TCP port 8080. | The REST API carries client requests for authentication, classes, materials, assignments, quizzes, grades and synchronization. It also serves file operations, video streaming and the captive download portal. |
| WebSocket | Hub service on TCP port 8081; authenticated with the bearer-token handshake. | The WebSocket carries quiz synchronization, announcement pushes, enrollment decisions, presence updates and AI token streaming. REST reads remain authoritative when a client misses an event. |
| mDNS / Zeroconf | Advertise `_lara._tcp.local` on port 8080 within the LAN. | mDNS lets clients discover the Hub on the local classroom network. It is not used to discover a Hub across the remote tunnel. |
| UDP broadcast beacon | JSON beacon every 3 seconds to `255.255.255.255:8888`. | The beacon provides a fallback way for clients to find the Hub on the classroom LAN. Manual Hub address entry remains available when multicast or broadcast discovery is blocked. |
| HTTP Range requests | Video stream responses use HTTP 206; transfer cap is 2.0 MB/s per client. | Range requests let clients seek within a video and resume a video transfer after a connection drop. The Hub enforces the documented per-client bandwidth limit. |
| SQLite | SQLx SQLite database on the Hub; SQLite mirrors on Mobile and Desktop clients. | The Hub database is the authoritative store for classroom records and files metadata. Client databases hold account-scoped offline mirrors and queued work. |
| llama-server / GGUF | Hub-only inference using the configured GGUF model; final model is subject to evaluation. | `llama-server` runs the optional Socratic tutor on the Hub. Mobile and Desktop send tutor requests through the Hub and do not download or run the model. |
| Bearer token authentication | All REST routes except `/download`, registration and login require a bearer token; WebSocket begins with an authenticated `EVENT_HELLO`. | The Hub uses bearer tokens to identify the signed-in account and enforce role and class-ownership rules. The same authentication rules apply through Remote/Suspension Mode. |
| Cloudflare Tunnel | Optional, explicitly enabled per Hub for Remote/Suspension Mode; proxies Hub REST and WebSocket traffic. | `cloudflared` provides a saved remote route to the Hub while classes are suspended. It is a transport relay and does not replace Hub authentication, authorization or data storage. |
| Delta sync with sequence cursor | `sync_revisions.seq` is a strictly increasing integer; it is never a timestamp. | Clients request changed records after their saved cursor and apply the response with the new cursor in one local transaction. Receipts determine whether queued work becomes synchronized or remains rejected. |
| USB export | Class records are `.xlsx` or `.csv`; the Hub can write to a mounted USB target path. | The export contains learner rows, assignment and quiz point columns with maximum points, and totals. The export route can also return a download when no USB target path is supplied. |

*Table 3.x. Technology requirements specification for L.A.R.A.*
