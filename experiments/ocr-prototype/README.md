# Parsing teacher PDFs and Word files for the tutor (throwaway experiment)

Which text extraction, cleanup and chunking gives the on-device model the best retrieval, and what hardware the parser needs. Results and recommendation: [`results/REPORT.md`](results/REPORT.md). Not Hub code; nothing here is wired into `server/`.

Main work is in `text/` (text-layer PDFs and .docx, judged by retrieval). The first plan, an OCR comparison for scanned PDFs, is kept as an appendix (top-level scripts, `results/ocr_fallback_tables.md`).

## Inputs (not in git)

* `lesson.pdf`: the 62-page sample lesson from PR #337 (`experiments/rag-prototype/sample/lesson.pdf`) and its key `text/key_sample.json` (`sample/answer_key.json`, 40 questions + 8 not-in-lesson + 4 answer-seeking).
* `wells.pdf` (Wells *Text-book of Biology* vol. II, a 254-page scan with a text layer) and `key_wells.json`: only for the scanned appendix and the one-core timing.
* The variants are generated by `text/build_variants.py` from the lesson.

## Rerun (Linux, no root)

```bash
# tools in user space: micromamba -> python 3.12, then pip (poppler's pdftotext/pdftoppm must already be installed)
bin/micromamba create -y -p env -c conda-forge python=3.12 tesseract      # MAMBA_ROOT_PREFIX=$PWD/mamba; tesseract only for the appendix
env/bin/pip install reportlab pyphen python-docx pypdf pdfminer.six pdfplumber fastembed rapidfuzz   # appendix adds: rapidocr onnxruntime pillow numpy opencv-python-headless img2pdf
cd text
python build_variants.py ../in/lesson.pdf ../work/variants        # v0..v6
for e in extractors ablation bytype speed; do python run_text_experiments.py ../work/variants $e > ../results/exp_$e.md; done
CH_EX=pdftotext python run_text_experiments.py ../work/variants chunking > ../results/exp_chunking.md
CH_EX=pdftotext python run_text_experiments.py ../work/variants embed > ../results/exp_embed.md   # downloads bge-small-en-v1.5
python rss_probe.py pypdf ../work/variants/v0_orig.pdf            # peak RAM of one extractor in its own process
```

`text/` files: `lesson_model.py` (lesson PDF -> blocks), `build_variants.py` (PDF/.docx renderers), `pipeline.py` (extractors, cleanup steps, chunkers), `retrieval_eval.py` (BM25 on SQLite FTS5, key scoring, decline threshold), `run_text_experiments.py` (the tables), `rss_probe.py`, `wells_probe.py`.

### Scanned-PDF appendix

`prep_inputs.py` builds the photocopy-style input C; `run_all.sh` runs pdftotext, Tesseract and RapidOCR on A (Wells), B (clean lesson) and C (degraded lesson); `run_engine.py` is one run; `score.py` makes the tables (`OCR_OUT=<copy of out/> WELLS_PDF=wells.pdf python score.py`); `rechunk_eval.py` is the unused end-to-end retrieval script. `run_engine.py` still contains the DeepSeek/GLM/PaddleOCR/LightOnOCR/granite entries; they were abandoned (see the report).
