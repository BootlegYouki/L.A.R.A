# AGENT_BRIEF: instructions for the AI assistant running this bundle on the RX 570 PC

Give this whole file to the AI assistant (Claude or similar) that works on the teammate's Windows PC. You are testing a throwaway prototype of the L.A.R.A Hub AI tutor. L.A.R.A is an offline classroom app for Philippine public schools; the Hub answers learners' questions about the teacher's PDF by finding the right lesson part (retrieval) and asking a small local model to guide the learner (Socratic: point to the page, never state the answer). Read `README.md` first. The scripts are in this folder; `KEY_FORMAT.md` describes answer keys and `verify_key.py` checks them. `TEST_QUESTIONS.md` lists the sample questions.

## Machine
Windows 10/11, AMD RX 570 8 GB, 32 GB system RAM, llama.cpp **Vulkan** build. The baseline model is **Qwen3-4B-Instruct-2507 Q4_K_M** (about 2.4 GB, fits entirely in VRAM with 5 slots). The embedder runs on the CPU. The SSD may have only a few GB free: models can live on another drive (`-ModelsDir`).

## Goals (in order)
1. **Get it running on the GPU.** Run `setup.ps1` (tools, embedder and the Qwen3-4B baseline only; add `-ModelsDir D:\models` if the SSD is small), then `run.ps1`. Confirm in the llama-server log that the Vulkan device is the RX 570 and that all layers are offloaded (`-ngl 99`). If it silently runs on the CPU, fix that before anything else. Report the device line. On a machine without a usable GPU, use the Qwen3-4B on CPU with 1 slot (`LLM_BACKEND=cpu`) and say it will be slow.
2. **Measure speed.** Run `gpu_bench.ps1` (the 4B only). Report prompt-reading (pp512, pp1024) and writing (tg128) tokens/s for the 4B on GPU and on CPU.
2b. **Compare every model, one at a time.** Run `bench_all.ps1 -ModelsDir <fast or big drive> -BigModelsDir <HDD or big drive> -Yes` (add `-Pdf2` and `-Key2` once you have the new PDF and key). It reads `models.json` and, for each model in turn: checks free space, downloads only that model, runs the full procedure (load check and load time, a discarded warm-up, llama-bench pp512/pp1024/tg128 on GPU, a CPU baseline up to 8B, the concurrency test at 1/3/5 users, the scored quality run with prompt V5), appends a row to `results/MODEL_COMPARISON.md`, then deletes that model (unless `-Keep`). Order: Qwen3-4B-Instruct-2507, Gemma-3-4B-it, Phi-4-mini-instruct, Qwen3-8B, Granite-4.0-H-Tiny, LFM2-8B-A1B, then the two optional MoE files last (Qwen3-30B-A3B REAP-15B and the original Qwen3-30B-A3B, experts in system RAM with `--n-cpu-moe` and `--no-mmap`). Peak disk need is the largest single model (about 18.7 GB for the 30B step, on `-BigModelsDir`). A model that fails to download or load is recorded and skipped. Stop with Ctrl+C and continue with `-Resume`. Use `-Only` for a subset. When it finishes, read `results/MODEL_COMPARISON.md`, name the best model for (a) 5 learners at once, (b) best answers regardless of speed, (c) best balance, and download the winner with `-Install <name>` for the rest of the work. State which drive type held the models (the file records it) and, for the MoE rows, the paging numbers: the MoE-on-CPU speed depends heavily on this PC's CPU and RAM bandwidth, so say so. After the 4B passes, say which is the smartest model that keeps p95 first token <= 10 s at 5 users, and compare answer quality on the new-PDF key with the same flags.
3. **Serve at least 5 chats at once** (on the new PDF from the section below). The target is **5 simultaneous learners** on one Hub PC. Start the model with 5 slots (`LLM_SLOTS=5`, context = 2048 per slot; this is the GPU default) and run `concurrency_test.py` with 1, 2, 3, 5 and 8 simultaneous users. "Fast enough" means, at 5 simultaneous users: **p95 time to first token at most 10 seconds and every stream at least 8 tokens/s**. If it misses, try (in this order) 4 slots, a cap of 2 chunks (`MAX_CHUNKS=2`), the sentence rerank `compress` mode, a smaller `-ub`/`-b`. Keep the best setting and say what it was. Do not accept a setting where the 5 users get wrong answers because the prompt was cut.
4. **Make the prompt better, because the hardware is faster.** The prompts live in `prompts/`. V1 is the Lead's contract prompt (do not edit it), V2/V3/V4/V5/V6 are experiments; V5 is the short one made for a slow CPU and is the default, V6 is V5 plus extras. With a GPU a longer, clearer prompt costs little. Compare V1, V2, V4, V5 and V6 (`python rag_eval.py --generate all --prompt V1,V2,V4,V5,V6`, about 10 to 20 minutes on this GPU). If you find weaknesses, write a **V7** that works better with the model you chose, add it next to V6 (a new file in `prompts/` and one line in `VARIANTS`, `CODE_LANG_GATE`, `GUARDED` and, if it uses the opener, `PAGE_PREFIX` in `rag.py`, and the dropdown in `index.html`), and report the table.


## Use a NEW PDF, not the sample (do this before the prompt work)
The sample lesson was written to be easy to check, and we have tuned on it. To see whether the pipeline really works, test on a **different, real** document.
1. **Get a new PDF.** A long (80 to 300 pages) text-based educational PDF in English that resembles what a teacher would upload: a DepEd Learning Module or Learner's Material (publicly posted on DepEd's learning resource portal), a free open-licensed textbook (for example OpenStax), or a long public-domain handout. Prefer a science or math book for Grades 7 to 10. Do not use a PDF with real learners' names, LRNs, photos or other personal data. Do not use paid or restricted textbooks. If a scan (no selectable text) is the only thing you find, say so: the Hub has no OCR, so it will produce zero chunks and the tutor cannot use it. That is expected, not a bug; report it.
2. **Check it extracts.** Run `pdftotext` on it and look at 5 random pages: reading order, tables, formulas, headings. Report what is garbled (math, multi-column text, tables). Then upload it in the page (not the sample button) and note pages, chunks and ingest time. A 200-page book can take several minutes to embed on the CPU; you may start the embedder with GPU offload to speed this up (say so if you do).
3. **Build your own answer key** (the old key does not apply). Read the PDF text yourself and write **30 questions**, each with the exact quote and its page, in the same format as `answer_key.json` (see `KEY_FORMAT.md`): 10 direct facts, 6 paraphrased questions that share almost no words with the text, 4 table or list items, 4 near-duplicate pairs (two similar facts on different pages, ask about one), 3 questions that need two adjacent sentences, 3 questions the book does NOT answer. Use page numbers exactly as `pdftotext -f N -l N` counts them (PDF page order, not the printed numbers; say which you use). Run `python verify_key.py your_key.json your.pdf`, which checks that every quote is on its stated page; fix the key until it passes. Never write a question you cannot back with a quote.
4. **Run everything on the new PDF:** `python rag_eval.py --key your_key.json` for retrieval (all four retrievers, rerank off/on/compress), then the concurrency test and the prompt comparison with `--key your_key.json`. Report the retrieval table and the prompt table **for the new PDF next to the sample's numbers**. If the new PDF is clearly worse, say where (headings missing, tables flattened, formulas garbled, chunks too big or too small) with examples; that is the most valuable finding.
5. **Do not commit the PDF** (copyright and size). Commit only the key file with a note of the PDF's title, source URL, license and page count.

## Rules the tutor must follow (do not weaken them to look good)
- Never state the final answer (the number, name, date or term that answers the question) and never quote or list it. Lists and steps are never written out.
- Always point the learner to where the answer is: the **page and heading**, in varied natural wording (not always "Look at"). The app currently writes the page sentence itself and the model continues it; you may keep that or have the model write it, but the page must always be right.
- Then say what to look for and ask ONE short question.
- Never say "I can't give you the answer" and never talk about rules.
- If the lesson does not cover the question, say so; never answer from general knowledge; never invent a page.
- English only. Filipino or Taglish messages get the exact line: "I can only help in English. Please ask your question again in English." (the app checks this itself).
- If asked for the answer ("just tell me", "no hints"), stay friendly and send them to the page the same way.

## How to judge a prompt (use the numbers, not impressions)
`rag_eval.py --generate` flags each reply: LEAK (answer value in the reply), LEAK_PASSAGE (a list item or long passage copied; list questions only), REFUSAL_PHRASE, BAD_CITE (page not sent), EMPTY, REPEATED_TEMPLATE, plus whether the reply names the right page. A better prompt has fewer LEAK/REFUSAL_PHRASE/BAD_CITE/EMPTY and more right-page replies, without longer first-token times. Look at 15 real replies yourself and quote 5 good and 5 bad ones in the report. A bigger model should beat a smaller one on these; if it does not, say so.

## Hard limits
- Do not modify anything outside `experiments/rag-prototype/`. Do not edit `contracts/`, `rules/` or the root files. Do not push to `main` or `staging`. Do not open pull requests.
- Do not commit model files, logs or personal data. Never put credentials, user names or LAN addresses in a file or a message.
- Commit your results to a NEW branch `experiment/rag-prototype-gpu-results` (results files, your V7 prompt if you wrote one, any script fixes). Do not push unless the user tells you to.
- The prototype has no login and is meant for one trusted Wi-Fi only. Do not expose it to the internet.
- Say plainly what you could not verify. Do not claim a number you did not measure.

## What to report back (put it in `results/REPORT.md`)

2. Speed table (pp512, pp1024, tg128; GPU and CPU).
3. Concurrency table: users 1, 2, 3, 5, 8 with p50/p95 time to first token, per-stream tokens/s, total tokens/s, errors.
4. Prompt table V1, V2, V4, V5, V6 (and V7) with the flags above and right-page rate.
5. Your V7 text if you wrote one, why you wrote it that way, and what still fails.
6. Anything that broke on Windows (exact error text) and how you fixed it.
7. `results/MODEL_COMPARISON.md` (and the file `results/<computer>-<date>.md`) as produced by `bench_all.ps1`.
8. A 5-line summary: can one RX 570 Hub serve 5 learners at once, with which model, settings and prompt?
